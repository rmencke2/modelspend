# Changelog

## Unreleased (planned as 0.8.0b4, with more to come: the version number in the code is bumped when it is tagged)

- **OpenAI retired `gpt-4.1-nano` between 2026-10-23 and 2026-10-27** (HTTP 404, "has been deprecated", seen live), the model the caching check had used. The provider's own answer is the only way to learn this: the catalog still lists it as available. `examples/caching_live_check.py` now explains a refused model and what to run instead of printing a traceback.
- **`modelspend duplicates` (new, not yet run on real traffic).** Requests sent more than once, word for word, with the cost of the repeats (every send after the first), a pattern (burst: repeats within a minute, usually a retry loop or a client resending after a timeout; later: the same input hours or days on; mixed), the project, agent and model, and what to do. It keeps per request of at least 200 characters one keyed hash (HMAC with the random key in your own database) of the messages, tools, schema and temperature, never the text; shorter requests are not tracked (a short prompt could be guessed and confirmed against its hash). On by default; `"track_duplicates": false` or `MODELSPEND_TRACK_DUPLICATES=0` turns it off, `modelspend duplicates --forget` erases it, `prune` removes old rows. Failed requests and ModelSpend's own shadow and eval runs are excluded. Both the `run` and `stream` paths are covered by tests, each shown to fail when its hook is removed. Details in docs/duplicates.md.
- **`modelspend digest` (new, not yet run on a real ledger or a real webhook).** The last day (or `--period week`) against the one before it: spend and the change, the three projects that moved most, the models behind it, budgets near or over their limit, and flags only when true (spend at least doubling by at least $0.50, spend after a silent period, calls with no price, a failure rate above 20%, more than 30% of tokens on retries and judge calls). Built from the same ledger as `modelspend report`. `--post` sends it to one webhook you configure (`"digest": {"webhook": ..., "format": "slack|discord|json"}` or `MODELSPEND_DIGEST_WEBHOOK`): off until set; project names are left out of what is posted unless `--include-projects`; https only (http for localhost), no credentials or query in the address, redirects not followed, and the address is never printed, logged, put in an error or shown in a config repr. Cron example in docs/digest.md. Tested against fakes only, including a test that no network call is made without `--post`. **First run on a real ledger (2026-10-24, 165 requests over a week) read sensibly, with one false alarm now fixed:** 20 calls recorded before `deepseek-flash` was priced made the week say "price it with `modelspend catalog price`" although the price had been set; they are now reported as earlier calls that ran before the model was priced (new calls are costed).
- **`modelspend doctor` (new, not yet run on a real setup).** One offline pass that says what is wrong and the command that fixes it; it sends nothing, spends nothing and creates no files. Problems (exit status 1): no key; a provider with a key but no usable model (names the commonest reason and the sync command); a failed last `verify`; a keys file or its folder readable by other users; a server set to listen beyond this machine with no API token; a settings file that does not load. Warnings: stale or undated prices; cached tokens reported for a model with no cached-input price (they are costed as plain input, overstating the cost); calls with no price; a failure rate above 20% with the commonest error; a provider enabled without a key; a world-readable ledger. Notes: a provider never checked live, an old pass, no traffic yet, Claude traffic with cache markers off. `--format json` for scripts. **First run on a real setup (2026-10-24) showed four false or noisy findings, now fixed:** providers left out of your enabled-providers list on purpose were reported as problems (now a note with `modelspend providers enable <name>`); a provider with a key but no models was a problem although other providers worked (now a warning; "nothing at all is usable" is the only problem); 20 calls from before a model was priced kept warning after the price was set (now a note: new calls are costed); and six providers never checked live took six lines (now one, with `modelspend verify --cache`). To support it, `modelspend verify` now keeps its last result per provider (verdict, model, date and the names of the checks that failed; no keys or text) in `verify-results.json`.
- **Anthropic cache markers (opt-in).** Claude caches only what a request marks with `cache_control`, so until now `modelspend caching` could only tell a Claude user that a repeated prompt was not being cached and that ModelSpend could not fix it. `"anthropic_cache_markers"` in settings.json (or `MODELSPEND_ANTHROPIC_CACHE_MARKERS`) is `off` (default; requests unchanged), `repeats` (mark a prompt start only after the same one was sent to the same model in the last five minutes, so a prompt that never repeats never pays the write premium) or `always`. One prefix is marked, the longest that qualifies, on the system block or on the last block before the final message. The advisor now subtracts the cache-write premium from "saved so far" (it can go negative), no longer counts the request that wrote the cache as a miss, and its Claude advice says how to turn the markers on, or why markers that are on produced no hits. `repeats` refuses to start with prefix tracking off. **First live run on Anthropic (2026-10-24, `claude-haiku-5-5`, `examples/caching_live_check.py`): it worked as designed.** Call 1 unmarked, call 2 wrote 7,489 tokens, calls 3 to 12 each read 7,489 (about 7,503 input tokens per call); the time-first prompt was never marked and got no writes or reads, so it paid no premium, and the table named it. The run also showed our prefix estimate undershooting Claude's own tokenizer (6,193 against 7,489), which clipped the cached tokens and the saving the table reported; the provider's own count is now believed up to the request's total input. The rerun showed 74,890 cached tokens, nothing missed and $0.0066 saved, which matches the catalog prices (74,890 x $0.09/M less the one write's $0.025/M premium on 7,489 tokens) by hand.

- **`modelspend caching` could not see the commonest caching mistake, and one of its explanations was wrong.** Found by simulating a timestamp at the top of a system prompt before the first live check (a fake provider, not yet seen on a real one): every request had a different prefix, so each was "seen only once" and the table said nothing, although the docs promised it would name a timestamp. It now keeps a second keyed hash per prefix with numbers, dates and ids blanked, and reports prefixes that differ only in those as "differs between calls only in numbers, dates or ids", with the potential saving priced as for a repeat. It cannot see changes in the words or in the order of items. Separately, an identical prefix that was repeated but reported no cached tokens used to be blamed on "the start of the prompt probably changes", which cannot be true of an identical hash; it now lists the real causes (below the model's minimum cacheable size, a model that does not cache, an expired cache) and points to `modelspend verify <provider> --cache`. Existing databases get a nullable `hn` column on first open; sightings recorded earlier have none and show no drift. New: `examples/caching_live_check.py`.

- **xAI, prepared (not run against xAI: it needs a key with credit; rehearsed through the real CLI against a local fake with xAI's documented quirks).** (1) **`modelspend verify` now checks how reasoning tokens are counted, from the provider's own totals.** The OpenAI-compatible adapter decides whether reasoning tokens sit inside `completion_tokens` from a per-model catalog flag that defaults to "inside", but xAI is documented to report them separately (`total_tokens = prompt + completion + reasoning`): a synced xAI reasoning model would have had its output silently undercounted unless someone remembered `catalog price --reasoning-separate`. The adapter now carries the provider's raw usage numbers (counts only) on the response, and when a reply contains reasoning tokens `verify` compares `total_tokens` with `prompt + completion` and `prompt + completion + reasoning`, reports whether that agrees with the catalog, and on a mismatch FAILs with the exact fix (`modelspend catalog set <model> pricing.reasoning_in_output=false`, which works on an unpriced model). When the numbers do not decide it, or the reply has no reasoning tokens, it says inconclusive instead of guessing. This also answers the open DeepSeek question about reasoning accounting the next time `verify deepseek` is run on a model that thinks. (2) **An xAI account with no credits answers HTTP 403** ("...doesn't have any credits or licenses yet"), which was classified as an auth error; it is now `quota` (an empty account: NOT VERIFIED, and failover applies), while a plain 403 is still `auth`. The wording of (2) is from memory of xAI's documentation and has not been seen live.

The cache check can now use up to ~16,000 input tokens (the cost bound printed before the run covers it). - **First live Gemini result (2026-10-20, `gemini-flash-latest`, free tier): partly verified, and the rest was stopped by latency, not by the adapter.** Passed: the key (63 models), an unknown model failing as `bad_request` (Google's 404 is classified correctly), and a completion reporting usage as the adapter assumes: `8 in + 0 cached, 93 out (of which 92 reasoning)`, i.e. Gemini's separately reported thinking tokens are added into the output count. **That one-word answer took 43 seconds.** The streamed call then hit the 60 s limit ("the stream stalled for 60s", the first chunk of a thinking model arrives after it has thought) and so did the 1,500-token cache call. Those are timeouts on a slow thinking model, not evidence about stream usage or cached tokens, which remain **unverified for Gemini**. (2) **`modelspend verify` now scales its allowance to the model**: after the first answer it allows three times that latency (at most 300 s) for the remaining calls and says so ("slow model (43 s for a one-word answer): allowing 129 s per call from here"), the hard per-call cap grows with it, and `--timeout <seconds>` sets the starting allowance. It now picks a model the key can see (a priced one if there is one, never a retired one), says that no cost is shown, and prints that the cost bound excludes unpriced models instead of "$0.0000". The `--cache` check no longer gives up when the first repeat shows no cache hit: providers that build their cache a few seconds after the first call (DeepSeek documents this) were reported as "inconclusive", so it now waits 5 s and repeats once, and says so when the cache was only there after the wait. The worst-case cost bound covers the extra call. **This was rehearsed against a fake, not DeepSeek: the live check still needs a key.**

## 0.8.0b1 - 2026-10-20

- **`modelspend catalog remove <provider/id or pattern> [--yes]`.** Takes back models you added (by `catalog sync --add-new`, `import-openrouter` or by hand), for example `modelspend catalog remove 'openrouter/*:batch' --yes`. Dry run unless `--yes`; shipped models are never touched (it points you to `models disable`); hand-set patches on a removed model go with it (a leftover patch would make the whole catalog refuse to load); the catalog is re-validated afterwards and the old file is restored if it would not load; the previous file is kept as `overrides.json.bak`; aliases that pointed at a removed model are named. Found needed when a first real `import-openrouter --write` (made before the `:batch` fix) added six batch variants and there was no way to take them back without editing JSON.
- **OpenRouter importer, first live run (2026-10-20, dry run, no key needed):** the response parsed as documented, ids with slashes came through intact, and the three OpenAI models' prices matched the ones already in the maintainer's catalog ($2/$8, $0.40/$1.60 and $0.10/$0.40 per million). It also showed something the fakes could not: OpenRouter lists a `:batch` twin of each model at exactly half the price. Those are now skipped with a stated reason (`not imported (n): ... batch-priced variant ...`) unless you pass `--include-batch`, because they appear to be asynchronous and a live request routed to one would not behave like the original, and they would otherwise appear as the cheapest model everywhere. How OpenRouter serves them has not been confirmed. Other id suffixes (such as `:free`, handled already) are unaffected; any other suffix is imported as listed.
- **Prompt-caching advice: `modelspend caching`.** Shows which long prompt starts (system prompt, few-shot examples, a document, plus tools and schema) repeat in your traffic, how many cached tokens the provider actually reported for them, how many it missed, what caching has saved you and what is still on the table, with the likely reason when a repeated prefix is not being cached (for example a timestamp near the top of the prompt). It credits repeats to the longest prefix that repeated, so nothing is counted twice; savings use your catalog's cached-input price and say so when there isn't one. Anthropic needs explicit cache markers, which ModelSpend does not send yet, so those rows are information only; providers other than OpenAI, DeepSeek and Anthropic are reported as "unknown" rather than assumed, with `modelspend verify <provider> --cache` as the test. **Storage:** per request, for each prefix of at least 1,024 estimated tokens, a keyed hash (HMAC with the database's own random key) and a token count; never text, nothing is tokenized for short prompts, a tracking failure cannot affect a request, `"track_prefixes": false` turns it off, `modelspend caching --forget` erases it and `prune` removes old rows. Also `GET /v1/cache-advice` and a Prompt caching table on the dashboard's Savings tab. Checked by breaking the window rule, realized/missed arithmetic, longest-prefix rule, write premium, provider kinds, tooling exclusion, salt use, token minimum, both engine hooks, the never-fail guard, forget, prune and the settings check on purpose: each break fails a test. **Not yet run on live traffic.**
- **`modelspend verify`: a live check of a provider on your own key.** A few tiny requests per provider (it asks first and prints the most it can cost, a fraction of a cent) check what the cost numbers depend on: the key works, an unknown model fails with a classified error, a completion reports non-zero token usage, a stream reports matching usage, structured output parses where the catalog claims it, and with `--cache` that cached tokens are counted once. FAIL means a number for that provider would be wrong; the Markdown report (`--report`) holds ids, counts and error kinds only. This exists because fakes cannot find the failures that matter most (a provider that reports no usage on a stream, or counts cached tokens differently from the adapter's assumption); first live runs (2026-10-20): OpenAI `gpt-4.1-nano` passed every check, including cached tokens counted once (183 uncached + 1,152 cached = 1,335, the same total as the uncached first call), and a local Ollama model passed key, errors, generate and stream; DeepSeek, Gemini, xAI and OpenRouter are still unchecked. The stream line now shows cached tokens too (it printed only uncached input, which made Ollama's cached repeat look like "1 in"). The checks themselves are tested against fakes that break each rule in turn, and each rule's test fails when the rule is removed.
- **A shareable report: `modelspend share`.** Writes one static HTML file (or `--format md` to paste into an issue or chat): spend, the projected saving, the evidence per task type, spend by model and the what-if table, with the caveats printed on the page. Built from the same functions as `savings` and `whatif`, so it cannot say anything they don't. Safe to hand over by construction: numbers, model names and task types only (no prompts, responses, keys or paths); project names appear only with `--include-projects`; ModelSpend's own eval and shadow runs are never listed; the HTML has no scripts and no network access (a Content-Security-Policy forbids both), every value is escaped, and it follows light and dark mode and works at phone width. The dashboard's Savings tab has download buttons for the same file (they send your API token if you set one). `GET /v1/share` serves it. Checked by rendering it in a browser (light, dark, 390 px) and by breaking the escaping, the CSP, the project default and the projection label on purpose to confirm each is caught by a test. Also keeps every module importable on Python 3.10 and 3.11.
- **A day-one report: `modelspend whatif --from-export <file> --export-provider openai`.** Prices a provider's own usage export (the same CSV, JSON or JSON-lines files `reconcile import` reads, same `--map`) on every catalog model, so the table is there before ModelSpend has seen any traffic. Nothing is stored. An export has totals per model per day, so long-context price tiers and per-request context checks cannot be applied (the report says so), and cached tokens are split out once for providers that count them inside input. Rows without a cost column are priced from the catalog and counted; models in the file that your catalog has no price for are named with the commands to add them, and actual spend reads `unknown`, never a misleading `$0`. Shipped models that no `catalog sync` has confirmed yet are now listed and flagged (`availability unverified`) instead of hidden, so a fresh install gets a table from the four shipped Anthropic prices; with nothing priced at all it says what to run. `cache_read` and `cache_write` are accepted as export column names. Checked by hand on a real OpenAI export (three dated model names matched the catalog; the totals recomputed to the cent). Two wording fixes from that run: an export with no cost column calls its spend an estimate from catalog prices, not an invoice, and it no longer claims ModelSpend's own eval and shadow runs are excluded (an export covers everything billed on the key, so it prices all of it).
- **What-if price table: `modelspend whatif`.** Replays the tokens in your own usage ledger (input, cache reads and writes, output, per billed attempt) against every priced model in your catalog and shows what the same traffic would have cost, cheapest first, next to your actual spend. It uses the same arithmetic as real accounting (`pricing.cost_for`, including long-context tiers and cache rates), so it cannot disagree with your ledger about a model you really used. Beside each price: the shadow evidence (passed/scored) and the task types where the model clears the same bar routing uses; models with no evidence say `unmeasured`, never "safe". Models with no known USD price are listed apart, never guessed; calls that exceed a model's context or output cap are flagged. A `total if moved only there` column prices your whole traffic with just the task types where the model clears the bar moved (everything else stays at what you spent), so the headline is never "all your traffic on the cheapest model". Models priced at $0 (local or free) are labelled as having no per-token price, with hardware and quality not counted. Filters: `--since`, `--project`, `--only`, `--provider`, `--profile`, `--all`, `--format json`. Also `GET /v1/whatif` and a table on the dashboard's Savings tab. It assumes the other model would read and write the same tokens, and says so. ModelSpend's own eval and shadow runs are excluded.
- **OpenRouter: a provider preset and a model importer.** `modelspend catalog import-openrouter --only <ids>` brings the models you name into your catalog with USD prices, context and output limits and advertised capabilities taken from OpenRouter's own model list (dry run by default; `--write`, `--refresh`, `--file`, `--include-free`, `--default-max-output`). It never invents a tier: untiered models are not chosen on a prior, but shadow evaluation can measure them. The response is treated as untrusted (size cap, every number checked, names cleaned, odd entries skipped with a reason). Model ids containing a slash (`openrouter/openai/gpt-4.1`) work throughout, and the savings report no longer truncates them. Tested against fakes of the documented response shape; **not yet run against the live OpenRouter API**.
- **More providers: DeepSeek and anything OpenAI-compatible.** A small provider registry (`src/modelspend/registry.py`) is now the one place that knows which providers exist. DeepSeek is a built-in preset (key, address, `max_tokens`, and its `prompt_cache_hit_tokens` counted as cached input); any other OpenAI-protocol endpoint (Groq, Together, Mistral, OpenRouter, a local Ollama or vLLM, ...) is described under `custom_providers` in settings.json and validated strictly (https only except localhost, no credentials in the URL, no name that clashes with a built-in, unknown settings are errors). Keys, `providers list`, pricing sources, reconciliation, provider options and the dashboard all read from the registry. No models or prices are shipped for these providers: take them from the provider's API and pricing page (docs/providers.md). **Tested against fakes; checked live only as far as a local Ollama server (model listing, sync and pricing); not yet run against DeepSeek or a hosted third-party endpoint.** A model added from an OpenAI-style list has IDs only, so it stays unroutable until its limits and a tier are set: the refusal message and `catalog sync` now print the exact `catalog set` command.

- **First-run errors say what to run.** "No eligible model" now names the fix for the usual causes: `modelspend keys set <provider>` (no key), `modelspend catalog sync` (shipped models start as unverified until your key confirms them), and how to mark a capability you have tested. One hint per kind.

- **Packaging is checked on every push:** a new CI job builds the wheel, runs `twine check`, installs it into a clean environment and runs the installed commands, so a missing data file is caught before a release. Checked by hand first: the wheel ships the catalog, eval fixtures and dashboard.

## 0.7.0b1 - 2026-10-17

- **Shadow evaluation (off by default, opt-in).** A sample of real requests is also tried in the background on cheaper models and compared with the answer you used: your validators, else an
  exact match, else a judge model. Only verdicts, fixed reason codes, costs and token counts are stored; never prompts, answers or judge output. Capped per UTC month (worst case checked before every
  call), recorded in the ledger under `project=modelspend-shadow`, never for sensitive requests unless allowed, never delays the request. `modelspend shadow status|on|off|set`. See docs/shadow.md.
- **Savings projection.** `modelspend savings`, `GET /v1/savings` and a dashboard **Savings** tab: per task type, spend now, the cheapest model that clears the evidence bar (the same bar and 95% Wilson
  lower-bound logic routing uses, your thresholds respected), measured cost ratio and projected saving, and what is missing (more samples, below the bar). A projection, not a measurement.
- **Routing can use it.** `modelspend shadow apply` (shows what would change; `--yes` to apply; `shadow revert`) lets routing treat shadow results as evidence only where you have no eval evidence of your own.
  Answers from a model that qualified by shadow evidence are never used as a reference, so "close enough" steps cannot chain.
- Server: `GET /v1/savings`, `GET/PUT /v1/shadow` (switch shadowing on or off without a restart). SDK: `ModelSpend.wait_for_shadow()`. `modelspend prune` also deletes shadow comparisons (and previously
  would have kept them when there were no old requests).
- Found in live runs: a reasoning model (`gpt-5-mini`) returned empty answers at a 64-token output cap. A candidate cut off at the cap is now **not counted as a pass or a fail** and is shown separately; `shadow status` lists reason codes for every comparison (including the kind of provider failure); the judge's reply is read tolerantly (a sentence around the JSON is fine); `modelspend shadow reset` forgets stale comparisons. Run live twice on a small sample; see docs/shadow.md.

## 0.6.0b2 - 2026-10-16

- **Fix: reasoning models were scored as wrong when they ran out of output tokens.** Found with `eval calibrate --show-failures`: every `gpt-5-mini` failure was an empty answer (4,032 of its 4,156
  output tokens were reasoning, under a 400-token cap), so its 0/2 on analysis, rewriting and summarization measured the cap, not quality, and the stored evidence would have unfairly excluded it from
  routing. Calibration and the baseline arms of `eval run` now retry a cut-off call once with 1,024 more output tokens, judge the retry, record both calls in the ledger, skip the retry if it would
  break `--budget`, and label anything still cut off as truncated. `eval calibrate` prints the number of retries; `eval run` reports `output_limit_retries`. Routed (non-eval) calls are unchanged; see
  docs/limitations.md.
- **Fix: an ambiguous built-in calibration case.** `cal-extraction-2` asked for "every person named... in order of appearance" but expected only the three distinct people, so `gpt-4.1` and
  `gpt-5-mini` answered `[Maria Chen, Dr. Okafor, Luis Prado, Maria, Luis]` (a fair reading) and failed. It now asks for each distinct person once, using the fullest name. The built-in dataset
  is renamed `modelspend-calibration-v2` so evidence from the old wording is not mixed with the new.
- **Fix: a reused ledger double counted the first call.** `run_single` recorded the whole ledger on every call, so a second call on the same ledger (the new retry) re-recorded the first call's attempts.
  Each call now records only its own attempts.

## 0.6.0b1 - 2026-10-16

- **Usage reconciliation.** `modelspend reconcile import <file> --provider <name>` reads a usage export you download from the provider (CSV, JSON or JSON lines; numbers only),
  and `modelspend reconcile run` compares tokens and cost per model with ModelSpend's own records over the days the export covers (`--by-day`, `--tolerance`, `--exclusive`,
  `--check` for a non-zero exit, `--format table|csv|json`). It flags ModelSpend recording *more* than the provider billed; provider-higher is normal unless the key is exclusive.
  Cached-token semantics are per provider and overridable; model snapshot suffixes are merged; re-importing a source replaces it and overlapping imports warn. The file formats are
  based on documentation; the OpenAI completions-usage CSV export was checked against a real file (tokens only: it has no cost column), the others are not. Days with no usage (blank
  rows in the export) are kept as covered days, so ModelSpend calls on a day the provider reports empty are flagged. See docs/reconcile.md.
- **Fix: live `eval run` and `eval calibrate` spend was missing from the usage ledger.** Found by reconciling with OpenAI's export: about 35,000 tokens (about 190 requests) on one day
  were in OpenAI's numbers but not in `modelspend report`, because the eval commands ran without a usage store and `run_single` never recorded. Their calls are now recorded under
  `project=modelspend-eval` (`agent=calibrate` or `eval-run`, task `eval`), so they show in reports, the Costs tab and reconciliation, and can be filtered out with
  `--project` (checked live: a 48-call calibration was recorded in full and the ledger total equalled the printed spend). Stickiness is forced off for eval requests so recording cannot change routing. Evals run before this release were not recorded and cannot be recovered.
- **Reconcile output:** a ModelSpend row with zero tokens and nothing from the provider (a call that failed before billing) is no longer flagged, and the result line says why
  provider-higher rows are not flagged instead of "all rows within tolerance".
- **Fix: first use from two processes on one database could crash after the provider call.** `Store.salt()` selected then inserted, so two processes both seeing "no salt yet" made the
  second fail with `UNIQUE constraint failed: meta.k` (surfaced as a flaky concurrent-budget test, about 1 run in 6). It now keeps whichever salt won. Regression test included.

## 0.5.0b1

- **Your own evidence bars.** `modelspend thresholds set|list|remove`: per task category (or `*`) set how many eval cases a model needs (`min_n`),
  the pass rate it must show (`min_pass_rate`), whether that is judged on the conservative 95% Wilson lower bound (default) or the observed rate (`basis`),
  and whether a model may be chosen on its tier prior alone (`require_evidence`). Resolved field by field: category, then `*`, then the profile. A setting can
  only tighten `high_assurance`'s evidence requirement. Bars that cannot be cleared at the evidence's n are reported as such (with the n needed) instead of
  silently failing. Invalid settings raise an error.

  duplicate ids, unknown or misconfigured validators, validators that reject the `reference` or accept the `wrong` answer, enough cases for your bar);

  does. It uses the router's own functions, so the two cannot disagree.
- Observed live: the same model scored 19/22 on one calibration run and 20/22 on the next, so one run is one sample (documented). `--show-failures` showed both failures to be fair (a keyword trap and an instruction hidden in the ticket).
- `eval calibrate --show-failures` lists which cases each model failed and its shortened answer (printed only, never stored).

- Docs: docs/own-evals.md. Unit-tested (including a property test that the table and the router agree) and run live at small scale: 7 models on the 22 calibration cases of examples/evals/support-tickets-hard for about $0.13: six scored 22/22 and cleared the default bar, `gpt-4.1-nano` scored 19/22 (lower bound 0.67, below the bar) and is no longer chosen for classification; on the 8 held-out cases ModelSpend matched the premium model's pass rate (8/8) at about 77% lower spend, while the cheapest model missed one (7/8). Small samples: wide intervals, one model separated.
