# Limitations and roadmap

## Known limitations

- **Anthropic has been exercised live** (2026-10-12: model sync, routing, escalation, token-budget gating, streaming, dashboard; token counts and cost matched the provider's reported usage). **OpenAI has been exercised live for chat and streaming (provider-reported usage)** (2026-10-12, `gpt-4.1-nano` and `gpt-5-mini`: routing, input-token estimate vs provider count, reasoning tokens reported inside the output count, cost from catalog prices); **OpenAI structured output (`response_schema`, strict and non-strict) was verified live on `gpt-4.1-nano` (2026-10-15)**; OpenAI cached-token reporting is still untested, as is a comparison with OpenAI's billing page. Failover on a bad key was verified live (OpenAI auth error, not retried, Anthropic answered). The Gemini and xAI adapters implement the official SDK / documented API surfaces but were tested only against fakes shaped like the SDK responses. Not yet exercised live for them: request acceptance (e.g. `max_completion_tokens` and `reasoning_effort` on xAI; strict JSON-schema mode; Gemini `response_json_schema`), real usage-field semantics (Gemini thinking tokens, xAI reasoning tokens, cached tokens), streaming usage, count-token endpoints. The Docker code sandbox (`python_tests`) is likewise untested against a real Docker daemon.
- **Only Anthropic pricing ships**, verified 2026-10-12; OpenAI, Google and xAI have no shipped entries (OpenAI works once you add models and prices yourself). Model IDs/limits are not on the pricing pages and must be confirmed with `catalog sync` (see [catalog-verification](catalog-verification.md)). Users must add and maintain entries; the tool warns on staleness but cannot detect provider price changes by itself.
- **Reasoning models can run out of output tokens before they answer.** Found live (2026-10-16): with a 400-token cap `gpt-5-mini` spent almost all of it on reasoning and returned empty text on the harder calibration cases. In evals ModelSpend now retries a cut-off call once with 1,024 more tokens and labels what is still cut off as truncated (see [own-evals](own-evals.md)). **Routed calls are not changed:** if you set a small `max_output_tokens` and the router picks a reasoning model, the answer can be empty; with validators it is reported as `not_truncated` failed and may escalate, without validators the status is `truncated`. Give reasoning models room (a larger `max_output_tokens`, or pin a non-reasoning model for short answers). Sizing the cap automatically for reasoning models changes budget arithmetic and is not done yet.
- **Shadow evidence and savings (0.7) are untested live.** Shadow evaluation measures whether a cheaper model gave an answer *as good as the one you used* (validators, exact match, or a judge model), not whether the answer is correct; a judge model has its own biases; the projected saving assumes the sampled requests are typical and scales spend by a measured cost ratio. The monthly cap is checked per process. See [shadow](shadow.md).
- **DeepSeek and custom OpenAI-compatible providers (0.8) are untested live.** They are covered by tests against fakes that mirror the SDK response shape. A provider whose "OpenAI-compatible" API differs in a detail (usage fields, an unsupported parameter) may need a small fix; see [providers](providers.md). No models or prices are shipped for them.
- **Suitability is an estimate.** Tier priors are editorial; measured evidence from small fixture sets is statistically weak; validators check form and key facts, not truth.
- **Expected cost ≠ cost per success.** Selection minimizes expected first-attempt cost among suitable models; escalation cost is bounded by budget but not modelled probabilistically (no fabricated success rates).
- **Token estimates are approximate** (chars/4, or tiktoken if installed, which is OpenAI-specific); reservations add a 20% margin when approximate. With `MODELSPEND_EXACT_TOKEN_COUNTS=true`, the selected candidate's input count is replaced by the provider's count endpoint (Anthropic, Gemini adapters; unverified live) before the call; ranking still uses estimates.
- **Text only.** Images/audio/files are rejected explicitly. Tool calls are returned, never executed; tool use cannot be combined with a response schema.
- **Streaming**: tool calls arrive whole at the end; no escalation on streams; partial-stream cost is estimated.
- **Task categorization** is keyword-based (English-centric). Ambiguous prompts get the stricter category; use `task_type` for reliability.
- **Latency targets** are enforced only from locally observed history (≥ 5 samples).
- **Privacy**: no prompts/responses stored (only keyed hashes and token counts of long repeated prompt starts, for `modelspend caching`: see [docs/caching.md](caching.md); off with `track_prefixes: false`); but request text still goes to the providers you allow. The `sensitive` flag only restricts to providers you declared acceptable — ModelSpend makes no claims about providers' data handling.
- Single-process SQLite; not designed for multi-tenant hosting.

- **Unpriced models** can run with `allow_unpriced`; their cost is `unknown` and they are ranked by tier then tokens, not cost.

- **Automatic price refresh is LLM-assisted and unverified live.** It is tested with scripted models and a real browser against fake pages, but not yet against the real OpenAI/Google/xAI pages. Verification catches invented numbers, not a hostile page; review before applying (see [pricing-refresh](pricing-refresh.md)).
- **Budgets (0.3) are single-machine.** Enforcement relies on SQLite write transactions shared by the processes using one usage database; it is tested with threads and separate connections, not across machines or network file systems. Windows are UTC. USD limits count only priced calls. Not yet exercised against live providers.
- **Aliases and conversation stickiness (0.4) were verified live on a small scale.** Stickiness never weighs the cost of switching against the saving and does not measure prompt-cache effects; conversations are recognised by their first message (or `run_id`). See [aliases-and-stickiness](aliases-and-stickiness.md).
- **Your own evals and evidence bars (0.5) were run live at small scale only** (22 + 8 cases; one of seven models separated). Measured quality is only as good as your validators and cases; small n gives wide intervals; evidence is per task category and is not re-measured automatically. See [own-evals](own-evals.md).

## Roadmap

1. Verified catalog snapshots per provider, plus a script that diffs official pricing pages (when reachable) against the catalog.
2. Live smoke-test suite (opt-in, capped budget) per adapter; recorded-fixture contract tests from real responses.
3. Provider token-count endpoints in planning; prompt-cache aware estimates when callers opt into caching.
4. Larger, versioned calibration/held-out sets; per-user evidence dashboards.
5. Batch-API routing; multimodal inputs with explicit capability matrix; multi-turn tool-loop helpers (caller-driven).
6. Pluggable classifier and policy modules; budget alerts and notifications; provider usage import and reconciliation.
